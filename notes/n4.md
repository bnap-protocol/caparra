# Integration notes: N4, signers

Branch `node/n4`, crates `crates/bnap-signer-file` and
`crates/bnap-signer-process`, plus one additive change to `bnap-core`
(below). Normative sources: `spec/socket-draft-00.md` (sections 2, 4.2,
8.1, 9.1, 12), `spec/schemes/bnap-notes-draft-00.md` (2, 4.2, 6.2, 7.4,
10, 18.1), and the signer contract of `notes/n3-core.md` (the sealed
`CoreMessage`, `CappedSigner::for_change` with the store-backed change
ledger, `ChangeLedger`).

## Change to bnap-core (flag for the core re-gate)

`CoreMessage::signed_bytes()`: a `CoreMessage` now keeps the bytes its
digest is the tagged hash of (`S` for an offer, the Response's records
outside 240 to 1000 for an ack) and returns them. Additive: a private
field and a getter, no constructor, no behaviour change. The compile_fail
doctest that shows a `CoreMessage` literal cannot be built names the new
field, and `tests/sign.rs` gains
`a_core_message_carries_the_bytes_its_digest_hashes`.

Why it is needed: the `Signer` trait hands a signer only `&CoreMessage`.
A signer in another process cannot receive a sealed value, and without the
preimage the only thing it could be sent is the 32-byte digest, which is
exactly the "sign whatever 32 bytes you are handed" interface the seal
exists to prevent. With the preimage, the signer process parses the object
with bnap-core and recomputes the digest itself (see "Only messages
bnap-core built").

## Public API

### `bnap-signer-file`

| `keyfile` | `read(path)` (permission-checked, zeroizing), `parse(text) -> Parsed { keys, keysets }`, `LoadError`, `MAX_KEY_FILE` (1 MiB) |
| `keyset` | `UNIT`, `DERIVATION_PURPOSE` (`0x626e6170`), `DEFAULT_ORDERS` (32), `MAX_ORDERS` (64), `SEED_LEN` (16 to 64 bytes), `KeysetError` |
| `object` | `recompute(purpose, key, signed) -> [u8; 32]`, `ObjectError`, `MAX_OBJECT` (64 KiB) |
| `MAX_OUTPUTS_PER_CALL` | 256 outputs per `blind_sign` call |
| `Clock` | `Arc<dyn Fn() -> u64 + Send + Sync>` |
| `testkit` (feature `test-support`) | the shared Signer behaviour suite: `KEY_FILE`, `fixture()`, `issuer()`, `commit(store, value, price)`, `output(s)`, `limit`, `fresh_replay_key`, `check_and_unblind`, one `async fn` per check, and `run(signer)` |

Key file (TOML, mode `0600` or stricter, a regular file reached without a
symbolic link):

```toml
[[key]]
use = "offer"            # or "receipt"; one key, one use
secret = "<64 hex>"
not_after = 1794000000   # optional; the signer refuses after it

[[keyset]]
seed = "<16 to 64 bytes, hex>"
index = 0                # BIP-32 index; a new index is a new keyset
input_fee_ppk = 100      # default 0
final_expiry = 1830000000
active = true            # default true; false = inputs only
orders = 32              # default 32: amounts 1 .. 2^31
```

## Decisions

- **Only messages bnap-core built, also across the socket.**
  `FileSigner::sign_object` is the only signing path, in process too
  (`Signer::schnorr` calls it with `msg.signed_bytes()` and then also
  checks the signature against the sealed digest). It finds the key held
  for `purpose.key_use()`, checks `not_after`, and
  `object::recompute`s the message: the bytes must be a canonical TLV stream
  with no record in 240 to 1000; a placeholder `offer_sig` (or `ack`) is
  added and the result must pass `Offer::parse` (or `Response::parse`), every
  record rule included; the object must name the requested key; the digest
  is the object's own `sig_message()` (or `ack_message()`) and must equal the
  tagged hash of the bytes. Raw digests, 32 random bytes, a whole signed
  offer, an offer as an ack and an offer naming another key are refused
  before any key is touched. The signature is made with fresh auxiliary
  randomness (`thread_rng` of the `bitcoin` re-export) and verified before
  it is returned.
- **One key, one use.** The same secret listed twice (for one use or two)
  is refused at load. A key past its `not_after` signs nothing.
- **Keyset IDs are NUT-02 version 01, computed by the `cashu` crate**
  (`Id::v2_from_data`), checked against keysets A, B and C of notes draft
  18.1. Unit is always `sat` (notes draft 4.2); `final_expiry` is required.
- **Keyset derivation** (the draft leaves it to the issuer, ERRATA N4-1):
  BIP-32 from the keyset's seed, key for `2^i` at
  `m/1651401072'/0'/index'/i'` (`0x626e6170`, "bnap"; `0'` is Cashu's unit
  slot for `sat`). A path of its own keeps BNAP keys out of every keyset of
  a Cashu mint that reuses the seed (notes draft 4.2, "a BNAP key never
  appears in any other keyset"). One derived key is pinned in the tests and
  was checked with an independent BIP-32 implementation.
- **BDHKE and DLEQ through the `cashu` crate**: `C' = a·B'`
  (`dhke::sign_message`), the NUT-12 proof from `BlindSignature::new`, whose
  nonce is NUT-12's deterministic one, so the same output gets the same
  `C'` and proof (notes draft 7.4). The tests verify every proof with
  `BlindSignature::verify_dleq` and unblind with `dhke::unblind_message`.
- **`verify_unblinded`** derives `Y = hash_to_curve(secret)` with bnap-core,
  checks `C = a·Y` for the keyset's key of that amount, and answers `None`
  for an unknown keyset, another unit, an amount without a key, or a keyset
  past `final_expiry + 60` (notes draft 6.2 step 2, 10). Inactive keysets
  still accept inputs.
- **`blind_sign`** refuses, before touching the ledger: an unknown keyset,
  a settlement unit other than `sat`, an inactive keyset, a keyset past its
  `final_expiry`, an outcome past `keep_until + 60` (its record may be
  purged; no honest gate settles it), an empty batch, an output of amount
  0, more than 256 outputs, an amount without a key, a `B'` off the curve.
  Then `ChangeLedger::reserve` (one total per `ReplayKey`, first cap per
  status pinned, each output once) and signing. The ledger drops outcomes
  past `keep_until` plus a skew at most once a minute.
- **The process protocol** is length-prefixed JSON (4-byte big-endian
  length, at most 256 KiB), version 1, unknown fields and duplicate fields
  refused, every byte string hex. A malformed frame, another version or an
  unknown operation gets a refusal and the connection is closed; a refused
  request keeps the connection. The client opens one connection per call
  (no pooling) and bounds the whole call. Transport failures and timeouts
  are `SignerError::Unavailable`; protocol violations `Refused`; the
  server's own refusals map back to their `SignerError` variant.
- **Who may connect.** The socket is chmod `0600` right after bind, in a
  directory the group and others cannot write (or a sticky one), and every
  accepted connection's peer credentials are checked: the server's own user
  (read as the owner of the socket file it just created, which needs no
  `unsafe` call) or one of `allowed_uids`.
- **The client checks the process too**: a signature must verify under the
  message's key, a returned `Y` must be `hash_to_curve(secret)`, and blind
  signatures must match the outputs one to one by amount.
- **Optional store check in the process** (`ServeOptions::store`): with the
  gate's use store, the process signs only outputs reserved for the outcome
  in `outcome[rk].change_outputs`, in the outcome's unit; an unreachable
  store signs nothing. This is a third line behind the gate's
  `CappedSigner` budget and the store reservation it makes, against a gate
  or plug that calls the socket directly. The binary does not expose it yet
  (no store crate exists to open one).
- **Secrets**: never logged, never in `Debug` or an error. A TOML syntax
  or type error is reported by line and column only (the parser's own
  message quotes the line and can quote a value); a bad field by its name
  and table position. The file is read into a zeroizing buffer with its
  capacity reserved up front; hex secrets are `Zeroizing<String>`; held
  key pairs are erased on drop (`Keypair::non_secure_erase`), BIP-32
  intermediates are erased after derivation, and keyset keys are the
  `cashu` crate's `SecretKey`, which erases itself on drop.

| # | Where | Ambiguity | What the build does |
| --- | --- | --- | --- |
| N4-1 | notes draft 2.2, 4.2, 10 | How an issuer derives its keyset keys is not specified; only the test keysets are (`SHA-256("bnap notes test keyset L m")`) | BIP-32 at `m/1651401072'/0'/index'/i'` from a per-keyset seed; explicit keys can be imported with `NotesKeyset::from_secret_keys` |
| N4-2 | notes draft 4.2, 18.1 | Which amounts a keyset has keys for is not specified (the vectors use `2^0` to `2^15`) | `orders` in the key file, default 32 (`2^0` to `2^31`), at most 64; the keyset ID covers exactly the keys listed |
| N4-3 | draft-00 8.1, 6.4; overview signer | In process, `Recorded::unsigned_receipt` is the only way to get an ack message (R8 of N3). A signer in another process sees a well-formed Response under its receipt key and cannot tell whether the use store recorded that outcome | The process signs any well-formed Response under a receipt key it holds. A later protocol version could carry the `ReplayKey` and let a store-connected signer check the record's status and fields before it signs an ack |
| N4-4 | draft-00 9.1 `keys.not_after` | Whether the signer itself stops at `not_after` is not said (the client and gate checks are 9.3 and N3a-12) | The signer refuses after `not_after` (no skew); keys without `not_after` never expire at the signer |
| N4-5 | notes draft 17 ("Keys live in a separate signer process"), overview signer | No IPC is specified | Implementation protocol of this crate (`wire`), versioned; not part of the socket |
| N4-6 | notes draft 6.2 step 2, 10 | The final-expiry skew is stated for the scheme's check | The signer applies the same `final_expiry + 60` to `verify_unblinded` and signs outputs only until `final_expiry` |

## Known gaps

- **Key file owner** is not checked: comparing it with the process's user
  needs `geteuid`, which is `unsafe` through `libc` (the workspace forbids
  `unsafe`) or a new dependency. Run the signer as a dedicated user and
  keep the file in a directory only that user can write.
- **Windows**: `bnap-signer-file` loads key files without permission
  checks there; `bnap-signer-process` is `#![cfg(unix)]` and its binary
  exits with an error.
- **No `--store` in the binary** until a store crate exists
  (`bnap-store-sqlite` / `-postgres`); the store check is library-only.
- **No reload**: new keys or keysets need a restart (no SIGHUP).
- **The signer's ledger is in memory** (a second line, as bnap-plug
  documents): a restarted process starts it from 0. The bound across
  restarts is the use store's reservation the gate makes.
- **DLEQ proofs are not checked by the client** (it has no keyset public
  keys); `CappedSigner` does not either. Wallets and the scheme's client
  side verify them (notes draft 7.3), as the testkit does.
- **Zeroization is best effort**: `bitcoin`'s `Xpriv` is `Copy`, the TOML
  parser may copy a string it has to unescape, and moves can leave copies.
- **K_mac** is not in the signer: the `Signer` trait has no MAC operation,
  so the gate holds `K_mac` and passes it to `UnsignedOffer::new`.

## For downstream nodes

- **Gate (N9)**: take `Arc<dyn Signer>` from `FileSigner::load(path)` (in
  process) or `ProcessSigner::new(socket)` (separate process, recommended
  in production); both pass the same suite. Sign offers with
  `UnsignedOffer::new(&fields, Some(&k_mac))` and `signer.schnorr`, receipts
  only through `Recorded::unsigned_receipt`, and change and refunds only
  through `CappedSigner::for_change(signer, store, cap)`. Publish the
  manifest keys from `FileSigner::keys()` (`public_key`, `key_use`,
  `not_after`) and the notes pay entry's `keysets` from
  `NotesKeyset::{id, input_fee_ppk, active}`; serve NUT-01/02 from
  `public_keys()` and `final_expiry()`. A signer refusal or outage is
  UNAVAILABLE (`SignerError::code`). Bound change outputs per outcome
  (the signer bounds 256 per call, not per outcome).
- **Wallet (N10)**: keyset IDs are NUT-02 version 01 and can be recomputed
  from the served keys with `cashu::nuts::Id::v2_from_data`; every blind
  signature carries a deterministic NUT-12 DLEQ proof that
  `cashu::nuts::BlindSignature::verify_dleq` accepts.
- **Notes scheme (`bnap-scheme-notes`)**: call
  `cx.signer.verify_unblinded(keyset, amount, secret, c)` with the UTF-8
  bytes of `hex(K)` as the secret; the signer answers `None` for a keyset
  of another unit and for a note past its keyset's final expiry plus 60 s.
- **End to end (N15)**: start `bnap-signer --keys keys.toml --socket
  dir/signer.sock` with the key file `0600` and `dir` `0700`; wait for the
  socket to accept; point the gate's `ProcessSigner` at it. The test key
  file is `bnap_signer_file::testkit::KEY_FILE` (draft-00 test offer and
  receipt keys, a fixed test seed): test material only.
- **Store nodes**: nothing to do; the process's store check reads
  `UseStore::outcome` only.

## Tests

- `bnap-signer-file/tests/behaviour.rs` (feature `test-support`): the
  testkit suite against `FileSigner`, one test per check plus `run`.
- `bnap-signer-file/tests/keyfile.rs`: modes 644, 640, 604, 620, 602, 610,
  601, 660, 666 and 777 refused, 600, 400 and 700 accepted; a symbolic
  link, a directory, a missing and an oversized file refused; 14 malformed
  files refused with no secret in `Display` or `Debug` (a syntax error on
  the secret's line, a secret in a number field, as a field name, in
  `use`, short or non-hex secrets and seeds, a short seed, the zero key, one
  key for two uses, a keyset twice, no final expiry, 65 orders, an empty
  file); no secret in any `Debug`; keyset IDs of notes draft 18.1 (A, B,
  C); derivation determinism, what the ID and the keys depend on, and a
  pinned key; explicit keyset errors; `not_after`; final expiry with the
  60 s skew.
- `bnap-signer-file/tests/object.rs`: recomputation equals the
  `CoreMessage` digest for an offer and an ack; refusals listed above.
- `bnap-signer-process/src/wire.rs`: frames round-trip; another version,
  an unknown field, a short array, an unknown purpose and a duplicate field
  refused; frames above the limit refused on both sides; partial frames and
  idle reads time out.
- `bnap-signer-process/tests/binary.rs`: the testkit suite through
  `ProcessSigner` and the `bnap-signer` binary on a temporary socket, one
  test per check, plus `run` with `RUST_LOG=trace` and no secret in the
  log and the socket removed on SIGTERM; the socket is `0600`; a key file
  others can read stops the binary with exit 2 (no secret in stderr, no
  socket); a served socket is not taken over; over the wire, a digest, 32
  raw bytes, an offer as an ack, an offer under the receipt key, an offer
  naming another key and a Response naming the offer key are refused and
  the connection then signs the real offer; malformed frames, version 2, an
  unknown operation and an oversized length are refused and close the
  connection while the server carries on; idle and slow connections time
  out; a gone or silent signer is UNAVAILABLE within its timeout.
- `bnap-signer-process/tests/store.rs`: an in-process server over a
  `MemoryStore` refuses outputs the store did not reserve, signs them
  through `CappedSigner::for_change`, re-signs reserved outputs, refuses a
  batch with one new output, outputs reserved for another outcome and an
  outcome without a record; an unreachable store signs nothing; without a
  store the suite passes in process too.
- `bnap-signer-process/tests/binary.rs`, client side: a fake process that
  returns a signature that does not verify, a `Y` that is not
  `hash_to_curve(secret)`, too few blind signatures, one of the wrong
  amount, or a reply of the wrong kind is refused by `ProcessSigner`.
