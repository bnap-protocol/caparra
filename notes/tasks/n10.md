## Maker brief

NODE N10: the client side. You own crates/caparra-wallet, crates/bnap-cli (binary "bnap") and crates/bnap-mcp (binary "bnap-mcp").
  - caparra-wallet: fetch + verify the manifest (duplicate-key rejection, root signature, max_age <= 30 days, pin root + backup per origin on first HTTPS contact, accept a new manifest only with higher seq signed by root or backup), verify offer_sig with an offer key the pinned root signed (unknown key: refetch once), honour bnap-required (never pay that origin natively until max_age lapses), spend policy in CODE (per-origin and per-task caps, allowed schemes, required properties from the registry vectors, linkability preference, experimental opt-in), ranking per the overview's Negotiation section (cost in the budget unit, rail fees, linkability penalty, server order breaks ties), never advertise capabilities, one value credential + attestations, notes wallet via the N6 client module (seed from BIP-39 mnemonic, NUT-13 derivation, recovery via restore NUT-09/07 against the issuer, local encrypted-at-rest store: SQLite file, key from a passphrase via argon2 or from the OS keychain if trivial), pay sources: NWC (pay_invoice) and an "lncli command" pay source for regtest, L402 and MPP clients, DPoP and Web Bot Auth client keys, receipts store (every paid action's Response, verifiable later).
  - bnap-cli: `bnap init` (new seed, shows mnemonic once), `bnap fund <origin> <sat>`, `bnap get|post <url>` (paid fetch with policy), `bnap budget` (show/set caps), `bnap receipts [verify]`, `bnap restore`. Every socket error code and wallet refusal maps to a short actionable message (e.g. SPENT, PENDING with retry-after, POLICY with which property failed, budget exceeded with the remaining cap, bad offer_sig, unknown key refetch failed). JSON output flag for scripts.
  - bnap-mcp: an MCP server (rmcp, stdio + streamable HTTP) exposing exactly three tools to any model: fetch_paid (url, method, body, max_sat), budget (get/set within limits the human configured, never raise above the configured hard cap), receipts (list/verify). The model never picks a scheme, never sets a cap above the configured hard cap, never sees keys. Structured tool errors with the same codes.
  Tests: wallet policy unit tests (prompt-injection style: a tool call asking to pay more or via a forbidden scheme is refused), manifest pinning tests (first contact, rotation with higher seq, backup key, downgrade attempt, bnap-required), ranking tests, an end-to-end test against a small in-test BNAP server built from bnap-core + bnap-carrier-http if available on develop (else from bnap-core directly) with fake rail, CLI snapshot tests for messages, bnap-mcp tool tests via rmcp client.
  Stop: tests/clippy/fmt green.
