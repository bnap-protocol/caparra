# Contributing

Thanks for helping with Caparra. This document covers how changes get in.

## Branches

- `develop` is the integration branch. Open pull requests against `develop`.
- `main` holds releases only. It moves forward from `develop` when a release is cut.

## Developer Certificate of Origin

Every commit must carry a DCO sign-off. There is no CLA.

By signing off you certify the [Developer Certificate of Origin 1.1](https://developercertificate.org/):
you wrote the change, or otherwise have the right to submit it under the
project's licenses. Sign off with `git commit -s`, which appends a line like:

```
Signed-off-by: Your Name <you@example.org>
```

Pull requests with unsigned commits cannot be merged. To fix the last commit,
run `git commit --amend -s --no-edit`; for a whole branch, run
`git rebase --signoff develop`.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):
`type(scope): summary`, for example `feat(core): parse price headers` or
`docs: clarify replay rules`. Common types are `feat`, `fix`, `docs`,
`test`, `refactor`, `chore` and `ci`. Mark breaking changes with `!`
or a `BREAKING CHANGE:` footer.

## Leak guard

The repository ships a pre-push hook that refuses to push private identifiers,
absolute home-directory paths or anything that looks like a secret (private
keys, nsec keys, API tokens, extended private keys, Lightning invoices).
Secret patterns are not checked under `vectors/` and `fixtures/`
directories, where test material lives. Enable the hook once per clone:

```sh
git config core.hooksPath .githooks
```

You can run the same check by hand at any time:

```sh
ops/leak-guard.sh
```

If it reports a finding, remove the offending text (and rewrite the affected
commits if the text is in history) before pushing. Do not bypass it with
`--no-verify`.

## Checks before a pull request

CI (`.github/workflows/ci.yml`) runs these on every push and pull request to
`develop` and `main`. Run them locally first:

```sh
ops/leak-guard.sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo nextest run --workspace --locked     # or: cargo test --workspace
cargo test --workspace --doc --locked
cargo deny check                           # needs cargo-deny
mdbook build book                          # needs mdBook 0.5
```

What CI runs, job by job:

| Job | What it checks |
| --- | --- |
| Leak guard | `ops/leak-guard.sh` over the tracked files and every new commit; on pull requests, a `Signed-off-by` line on every non-merge commit |
| Rustfmt | `cargo fmt --all --check` |
| Clippy | `cargo clippy --workspace --all-targets -- -D warnings` |
| Test | `cargo nextest run --workspace` and the doctests, on Linux and macOS |
| MSRV | `cargo check --workspace --all-targets` on Rust 1.94 |
| cargo-deny | Advisories (reported, not blocking), bans, licenses and sources (blocking), per `deny.toml` |
| Book | `mdbook build book` |
| Regtest e2e | `cargo nextest run -p e2e --features regtest` against `devenv/regtest/compose.yml`; skipped until that file exists |

The toolchain is pinned in `rust-toolchain.toml`. The minimum supported Rust
version is declared in the workspace `Cargo.toml`. `Cargo.lock` is committed
and CI builds with `--locked`, so commit the lock file with any dependency
change.

## Dependencies

- Add shared dependencies to `[workspace.dependencies]` in the root
  `Cargo.toml` and use them from a crate as `name = { workspace = true }`.
  `cargo deny` rejects a crate that declares its own version instead.
- The tree carries exactly one `secp256k1`, taken through the `bitcoin`
  re-export (`bitcoin::secp256k1`). Do not add `secp256k1` directly; `cargo
  deny` fails on a second version.
- Every dependency must be licensed under one of the licenses allowed in
  `deny.toml` and come from crates.io.
- Dependabot opens weekly update pull requests against `develop`.

## Documentation

The guide lives in `book/` (mdBook 0.5). Pull requests build it; every push
to `main` publishes it to GitHub Pages. A new chapter needs an entry in
`book/src/SUMMARY.md`: missing chapter files are a build error.

## Releases

Releases are owner-gated: only the owner pushes a release tag. Nothing is
published to crates.io.

- **Binaries** (`caparra-gate`, `bnap`, `bnap-mcp`) are built by
  [dist](https://opensource.axo.dev/cargo-dist/) 0.33 from
  `[workspace.metadata.dist]` in `Cargo.toml`, for macOS on Apple silicon and
  Linux on x86-64 and arm64, with GitHub artifact attestations.
  `.github/workflows/v-release.yml` is generated by `dist generate --mode ci`
  (dist names it after the `v` tag namespace) and runs only when a tag that
  starts with `v` is pushed. It builds the archives, attests them and creates
  the GitHub Release, marked as a prerelease when the version has a suffix
  such as `-alpha`. The CI workflow runs `dist plan` on every pull request,
  which also fails when the release workflow is out of date.
- **Library crates** are not published yet. `release-plz.toml` keeps
  `publish = false` and no workflow runs release-plz; once crates.io trusted
  publishing is configured for every crate, release-plz will write a
  `CHANGELOG.md` per crate and tag each crate as `<crate>-v<version>` (those
  tags do not start with `v` and never trigger the binary release).

To cut a release (the owner):

1. On a branch, set `[workspace.package] version` and the `version` of every
   internal crate in `[workspace.dependencies]` to the new version, run
   `cargo update --workspace`, and move the `[Unreleased]` notes in
   `CHANGELOG.md` to a section for the version and date.
2. Run `dist plan` (dist 0.33) and check that it announces
   `v<version>` with exactly `bnap-cli`, `bnap-mcp` and `caparra-gate`. After
   any change to `[workspace.metadata.dist]`, run `dist generate --mode ci`
   and commit the regenerated workflow.
3. Merge to `develop` and then to `main` through pull requests with green CI.
4. Tag the merge commit on `main` with `v<version>` (for example
   `git tag -s v0.1.0-alpha`) and push the tag. The release workflow builds,
   attests and publishes the GitHub Release.
5. Check the release: download an archive and run
   `gh attestation verify <archive> --repo bnap-protocol/caparra`.
